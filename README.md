# (Un)designing a Grocery Prediction Algorithm (PhD Project)
This repository contains the working code and data for an experimental grocery prediction algorithm to predict shopping lists for 'week nine'. The purpose of this project was to research the social and environmental implications of implementing automated data-driven grocery recommendations for grocery shopping practices. This project is part of the PhD thesis titled: "(Un)designing Learning Agents in Messy Domestic Contexts". 

# Data Collection
Over a period of eight weeks, split up into two four-week periods, participants (five households living in Belgium and the Netherlands) were asked to photograph all their grocery receipts and submit them via Telegram. 
The data collection was split into two four-week periods, separated by the Christmas holidays. While the seasonal festivities can be interesting in terms of disruption,
Data collection took place during the latest stages of the COVID-19 pandemic (end of 2021). This has an effect on the types of items that are bought, especially near the Christmas period during which people came together (and thus bought more face masks and COVID-19 tests, for example).
The data collection included receipts from supermarkets, bakeries, butchers, organic shops, and any other sources through which the participating households bought their
groceries. Each collected grocery receipt was transcribed and entered into a dataset, which recorded all purchases the households made during the receipt collection periods. The resulting dataset included, for each purchased item: item name as mentioned on the receipt, quantity, price (per unit and total), store name (e.g., Spar, Carrefour), date and time of purchase, and whether there was a promotion on the item.
This grocery receipt data served two purposes: (1) as a basis for the practice-based inquiries for this project, in which I continually refer back to the receipt data during the interviews with the households to inquire about the reasoning and circumstances behind their grocery shopping decisions, and (2) as the input data for the grocery prediction algorithm.

# Grocery Prediction Algorithm
The goal of the grocery prediction algorithm was to simulate the households’ grocery routines for one week (“week 9”) based on the eight weeks of collected grocery receipts. The resulting grocery recommendations for week 9 consisted of weekly schedules (when and where to shop) and grocery lists (what and how much to buy). The algorithm was programmed in Python code using Jupyter Notebooks.
## Three stages
The grocery prediction algorithm generated grocery recommendations in three cascading stages. First, recommendations were generated about when grocery trips would occur (i.e., shopping days and shopping times). These recommendations then informed where these grocery trips would take place (i.e., store name, which also implies store type). And finally, recommendations for when and where grocery trips would take place informed what (and how many) items would be bought from which category/aisle on each grocery trip (i.e., item counts and item lists, which also implies item categories). The grocery prediction algorithm was thus constructed as a cascading feature-by-feature pipeline in which each prediction informed the next.
## Four Steps
To generate the grocery recommendations, the algorithm followed a four-step approach. This deliberately simple four-step approach consisted of generating and constraining weighted samples from household-specific datasets, which proceeded as follows: 
1. Weights: To predict a target feature (e.g., shopping day, store, grocery item), the algorithm assigns weights to all possible output values based on their relative frequencies in the historical data. For example, if a household bought milk 10 times, eggs 8 times, and salad 5 times, these counts represent the weights that affect the likelihood of each item being generated in the next step.
2. Sample: Using the sampling weights that represent the frequency distribution of the target feature, the algorithm generates a random sample. For example, a sample of three grocery items might consist of two cartons of milk and one carton of eggs. The size of this sample (i.e., number of values to predict) is feature-specific (e.g., seven days in the week) or linked to preceding recommendations (e.g., two grocery visits on Tuesday).
3. Constraints: The sampled output is filtered using constraints based on household-specific historical data. For example, if a household never bought more than one carton of milk per trip, a sample that contains more than one carton for one grocery trip is rejected. These constraints ensure that recommendations are aligned with the household’s previous routines.
   - Steps 1 to 3 are repeated until the generated sample meets these constraints.
5. Prediction: Once a sample meets all constraints, it is accepted as a prediction for the target feature. For example, an accepted prediction for a three-item grocery trip according to the example constraints might be: one carton of milk, one carton of eggs, and one bag of salad.
   - These four steps are repeated for each feature in the three prediction stages. Each prediction feeds into the prediction of subsequent features.
## Two Models
To generate and filter the grocery recommendations, the algorithm relied on two stochastic models: (1) weights models based on value distributions of the target feature and (2) constraints models based on the upper and lower values of relevant features. These models are household-specific, which means that the grocery recommendations for each household were based on their own historic dataset.
